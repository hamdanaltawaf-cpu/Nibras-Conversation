# سياسة التسمية واللغة في مستودع YemReact

> **الحالة:** معتمدة من صاحب المنتج بتاريخ 2026-11-07.
>
> **النطاق:** أسماء المجلدات والملفات والوثائق ومحتوياتها داخل المستودع. لا تشمل تعريب واجهة تطبيق YemReact أو تنفيذ RTL.

## 1. اللغة الافتراضية

1. تكون العربية هي اللغة الافتراضية لأسماء المجلدات والوثائق التفسيرية الجديدة، ولمتن الوثائق التنظيمية التي نكتبها للمستودع.
2. تُعرب النصوص التفسيرية في الوثائق القائمة على دفعات لاحقة، مع الحفاظ على مضمونها وتاريخها وحدودها؛ ولا تُعدّل القرارات أو تُعاد صياغة الوقائع التاريخية بما يغيّر معناها.
3. تبقى أسماء العلامات والمنتجات والأدوات والمكتبات والمعايير التقنية بالإنجليزية عند كونها أسماء رسمية، مثل `YemReact` و`GitHub` و`React` و`PostgreSQL`، ويضاف شرح عربي عند أول ورود إذا احتاج السياق.
4. عند استخدام مصطلح تقني إنجليزي داخل نص عربي، يُستخدم المقابل العربي نفسه بصورة ثابتة في جميع الوثائق، ولا تُنشأ ترجمات متباينة للمفهوم الواحد.

## 2. أسماء المجلدات والملفات التفسيرية

1. تستخدم أسماء عربية واضحة تصف وظيفة المجلد أو الملف مباشرة.
2. تستخدم الشرطة الواصلة `-` للفصل بين الكلمات في الأسماء المركبة، مع تجنب الأسماء العامة أو المبهمة.
3. تُمنع الامتدادات المكررة مثل `.md.md`، وتُحفظ امتدادات الصيغ كما هي.
4. لا تستخدم أوصاف مثل «نهائي» أو «جديد» أو «نسخة أخيرة» وحدها لتسمية ملف؛ يذكر موضوعه أو وظيفته، ويضاف التاريخ أو رقم الإصدار عند الحاجة.
5. تبقى أسماء الملفات القياسية التي تعتمد عليها المنصات والأدوات كما هي، وفي مقدمتها `README.md`.
6. لا يُترجم اسم ملف كود أو إعداد أو أصل مرتبط بالتطبيق لمجرد أن بقية المستودع بالعربية.

## 3. المعرفات والمسارات التقنية المحمية

تبقى كما هي دون تعريب أو تغيير:
- معرفات القرارات والأسئلة والمقترحات والمراحل، مثل `DECISION-I01` و`DECISION-5B.23` و`OPEN-Q-08` و`P-37`.
- مسارات التطبيق مثل `/search` و`/r/:slug` و`/settings` و`/help`.
- أسماء المتغيرات والدوال والمكونات والحقول ومفاتيح البيانات وواجهات API وCSS classes وIDs وselectors.
- أسماء ملفات الكود والاختبارات والإعدادات وأوامر الطرفية والقيم التي تتطلبها الأدوات.
- امتدادات الملفات والصيغ وأسماء المنتجات والتقنيات الرسمية.

## 4. تعريب محتويات الوثائق

1. تُترجم الفقرات التفسيرية والعناوين والجداول والشروح إلى العربية مع الحفاظ على ترتيب الوثيقة وبنيتها.
2. تبقى المقاطع البرمجية والأوامر والمسارات والمعرفات والقيم التقنية دون ترجمة.
3. تُحفظ الاقتباسات والمراجع وأسماء أصحابها ومصادرها؛ ولا يُنسب النص المترجم إلى المصدر كأنه نصه الأصلي.
4. لا تُحذف التحفظات أو الاستثناءات أو حالات عدم التحقق أو عبارات «مقترح» و«تاريخي» و«غير معتمد».
5. لا تتحول صياغة قديمة إلى حقيقة حالية بسبب الترجمة؛ تُحفظ دلالتها الزمنية ويضاف تنبيه توضيحي منفصل عند الحاجة وبعد التحقق.
6. لا يُترجم ملف تاريخي أو وثيقة قرار حساسة قبل تحديد ما إذا كان المطلوب ترجمة المحتوى كله أو النص التفسيري فقط، وفحص أثر ذلك على الإحالات.

## 5. الترميز والروابط والسلامة

1. تحفظ الملفات النصية بترميز UTF-8.
2. تستخدم أسماء ومسارات عربية متسقة، وتُختبر روابط Markdown بعد أي إعادة تسمية؛ لا يُفترض أن تحويل المسار إلى العربية لا يؤثر في الروابط.
3. لا تُغيّر أسماء الأصول المرئية أو الملفات المرتبطة بالكود قبل البحث عن جميع مواضع استخدامها.
4. لا يُنقل ملف ولا يُعاد تسميته قبل إدراجه في خريطة النقل وفحص الإحالات إليه.
5. لا يُحذف ملف لمجرد قدمه أو تجاوزه؛ يحدد مصيره بعد تقييم قيمته التاريخية وروابطه، ويحتاج الحذف إلى موافقة صريحة إذا لم يكن فارغاً.
6. تُراجع كل دفعة تعريب بمقارنة النص الناتج بالأصل للتأكد من عدم سقوط معنى أو قيد أو استثناء.

## 6. حدود السياسة

هذه السياسة تنظّم اللغة والتسمية فقط. لا تمنح أي ملف سلطة قرار جديدة، ولا تغيّر المرجعية الكانونية أو قرارات المنتج أو حالة المراحل، ولا تُعد موافقة مسبقة على تنفيذ عمليات النقل أو إعادة التسمية أو الحذف.
